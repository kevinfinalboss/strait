strait is a TCP load balancer written in Rust, built in stages from a plain proxy up to an in-kernel data plane. It has health checks, hot reload, Prometheus metrics and Kubernetes discovery, plus an experimental XDP mode with Maglev hashing and direct server return.

What it does

Each feature arrived as a stage with its own tests and demo. Everything below runs today.

Three strategies

Round-robin, least connections, and ip-hash with rendezvous hashing: when a backend leaves, only its own clients move.

Failure handling

Active health checks with thresholds, connect retries on other backends, idle timeouts, and fail-open when every check fails.

Hot reload

A YAML config with many listeners, applied on SIGHUP or file change. A reload applies fully or not at all, and open connections keep their route.

Prometheus metrics

Connections, bytes as they move, connect and lifetime histograms, live per-backend gauges. Series of removed backends are cleaned up.

Kubernetes native

Backends from a Service's EndpointSlices, ConfigMap reload without restarts, a Helm chart, and graceful drain on SIGTERM.

EXPERIMENTAL

XDP data plane

An Aya program balances packets in the driver with Maglev tables and IP-in-IP. Backends answer clients directly; replies skip strait entirely.

Two data planes, one control plane

Per listener, strait either proxies connections in userspace or programs the kernel to forward packets. Backend discovery, health checks and metrics are shared by both.

Proxy (default)

strait accepts each TCP connection, picks a backend and relays bytes both ways on a tokio task.

XDP with direct server return

An XDP program picks a backend from a Maglev table, wraps the packet in IP-in-IP and sends it back out. The backend replies to the client directly.

Performance

The overhead strait adds over hitting the backend directly, measured with oha using demo/bench.sh. CPU per request is strait's own CPU time, which is far less sensitive to other load on the machine than requests per second.

50 connections for 10 s per run on an AMD Ryzen 7 5700G (16 threads) under WSL2, with the load generator, strait and the backend on the same machine. CPU per request is the backend's own CPU for direct runs and strait's for runs through it. A proxy that terminates TCP pays for two connections per client; the XDP data plane avoids that, and its benchmark is the next stage of the roadmap.

Quick start

Requires Rust 1.95 or later. Any TCP service works as a backend; these serve HTTP.

# build
git clone https://github.com/kevinfinalboss/strait.git && cd strait
cargo build --release

# two backends
python3 -m http.server 9001 --bind 127.0.0.1 &
python3 -m http.server 9002 --bind 127.0.0.1 &

# strait in front of them, with metrics
./target/release/strait -b 127.0.0.1:9001 -b 127.0.0.1:9002 --metrics 127.0.0.1:9090

# requests alternate between the backends
curl http://127.0.0.1:8080/
curl http://127.0.0.1:9090/metrics

The README covers the YAML config, Kubernetes and the Helm chart, the XDP build, and every flag.

Roadmap

strait is built in stages, from a plain TCP proxy up to an XDP data plane.

  • doneTCP proxy: bidirectional copy, graceful shutdown
  • doneLoad balancing: round-robin and least connections
  • doneHealth checks, retries and timeouts
  • doneSession affinity with rendezvous hashing
  • doneConfig file with multiple listeners and hot reload
  • donePrometheus metrics
  • doneKubernetes: EndpointSlice discovery, ConfigMap reload, Helm chart
  • in progresseBPF/XDP: the Maglev data plane works; benchmark against the proxy is next
  • nextDashboards: Grafana dashboard and a compose stack with Prometheus
